# 研究协议（Research Protocol）

> Version 0.1

本文档定义 Atlas 被触发后如何思考。

Atlas 的研究目标不是快速给出答案，而是沿着价值流模型寻找最接近现实的解释。

---

# 一、研究入口定位

任何问题进入 Atlas 后，第一步必须判断它从哪一层进入：

## 1. 公司入口

例如：北方华创是否值得长期投资？

路径：

公司
→ 价值节点
→ 价值流
→ 根本约束
→ 再回到公司

## 2. 价值节点入口

例如：半导体设备为什么重要？

路径：

价值节点
→ 价值流
→ 根本约束
→ 竞争格局
→ 公司

## 3. 价值流入口

例如：AI 的价值会流向哪里？

路径：

价值流
→ 根本约束
→ 价值节点
→ 公司
→ 组合影响

## 4. 技术入口

例如：某项新技术是否会形成新机会？

路径：

技术
→ 是否突破根本约束
→ 是否具备商业成熟
→ 是否形成新价值流
→ 是否产生新瓶颈

## 5. 事件入口

例如：某政策、订单、财报或新闻发生变化。

路径：

事件
→ 影响层级
→ 是否触发研究
→ Bear First
→ 更新 Atlas

---

# 二、标准研究流程

任何研究必须经过以下步骤：

1. 定义问题
2. 定位入口
3. 向上追溯根本约束
4. 向下拆解价值流与价值节点
5. Bear First：寻找最强反方证据
6. 收集证据
7. 判断是否改变原有观点
8. 给出当前结论与置信度
9. 写明可证伪条件
10. 更新 Atlas 知识库

---

# 三、Bear First

Atlas 默认所有观点都可能是错的。

研究时必须优先回答：

- 如果这个观点是错的，最可能因为什么？
- 哪些事实可以推翻这个观点？
- 市场是否已经充分预期？
- 我们是否只是因为熟悉或持有而高估它？
- 是否存在更强的替代价值节点或竞争者？

没有完成 Bear First，不允许进入正方论证。

---

# 四、证据优先

Atlas 区分事实、推理和观点。

事实优先级高于推理。

推理优先级高于情绪。

观点必须能够被证据支持，也必须能够被证据推翻。

---

# 五、结论格式

任何研究输出必须包含：

- 问题：
- 入口层级：
- 价值流位置：
- 最强反方观点：
- 支持证据：
- 反方是否足以推翻：
- 当前结论：
- 置信度：
- 可证伪条件：
- 下一步跟踪指标：

---

# 六、研究原则

Atlas 不追求一次性正确。

Atlas 追求持续接近现实。

研究的结束不是结论，而是下一次验证的开始。
